# CP07 — معمارية المحرك المعرفي الموحد

**HYBRID · OFFLINE-FIRST · EVIDENCE-DRIVEN · OPEN-SOURCE · MODEL-OPTIONAL**

## 1. المسار الفعلي المنفّذ

```
سؤال الموظف (عربي / يمني)
  │
  ├─ nlu.ts         فهم: intent · skin/hair · concerns · requested_product_type · ingredients · constraints
  │                 · sensitivity_flags · medical_red_flags · referrals · unknown_subject · confidence
  │                 (فوق understand() من CP06.2 دون تعديله)
  ├─ السلامة أولًا  علامة خطر → إحالة فقط، بلا معرفة ولا منتجات · سعر/مبيعات → خارج النطاق
  ├─ retrieve.ts    توجيه منظم (مفهوم → موضوع) + BM25 عربي (أو FTS5 حين يتوفر) على الادعاءات القابلة للاستخدام فقط
  ├─ answer.ts      تركيب حتمي: كل جملة = ادعاء (id + مصادر) أو جملة نظام ثابتة · «لا تتوفر معلومات موثوقة كافية»
  ├─ bridge.ts      منتجات المحل النشطة فقط → محرك الملاءمة CP06.2 (science/* دون تعديل) → شرح بالمكونات
  │                 · الملاءمة ≠ اكتمال المعلومات ≠ التوفر (ثلاثة حقول)
  ├─ (اختياري)      نموذج محلي يعيد الصياغة فقط → groundingCheck → عند أي فشل: نص LOCAL_RULES
  └─ growth.ts      الفجوة (مفهوم فقط) → مهمة → موصل مجاني (إن فُعّل) → دليل pending → إنسان يكتب الادعاء → اعتماد
```

الإنترنت ليس شرطًا (كل ما سبق محلي؛ الموصلات معطلة افتراضيًا). النموذج ليس شرطًا (LOCAL_RULES هو الافتراضي والرجوع).

## 2. الفصل بين الطبقات

| الطبقة | أين | لا تختلط بـ |
|---|---|---|
| معرفة علمية عامة | `knowledge_claims` + `knowledge_sources` | ادعاءات الشركات (مصنفة `manufacturer_claim` وتُحجب) |
| أدلة مكتشفة | `knowledge_retrievals` (موسّع) | المعرفة المعتمدة — لا تُستخدم قبل أن يكتب إنسان ادعاءً ويعتمده |
| سياق المحادثة | `advisor_sessions` (CP06.2) | المعرفة — النموذج لا يكتب في أي جدول معرفة |
| هوية المنتج | `products` (لا يُكتب فيه شيء من CP07) | الملاءمة (تُحسب عند الطلب ولا تُخزن) |
| التوفر | `products.availability` | الملاءمة |
| حالة المراجعة | `state` + `review_level` | — |

**Scientific Suitability ≠ Product Identity ≠ Local Availability** — مطبّق في `bridge.ts` وفي الاختبارات.

## 3. نموذج البيانات (الترحيل 008، إضافي)

| الجدول | الغرض |
|---|---|
| `knowledge_sources` | مصدر أصلي: نوع المصدر، مستوى الدليل، حالة الترخيص، **ارتباط بصناعة**، تاريخ الاطلاع/النشر، الأصل |
| `knowledge_topics` | 26 موضوعًا (بشرة، شعر، فروة، مكونات، روتين) |
| `knowledge_claims` | الادعاء: نص عربي مبسط + صياغة إنجليزية منظمة للمطابقة مع المصدر + حدود + تحذيرات + مستوى الدليل + الحالة + مستوى المراجعة + الإصدار + `supersedes` + المعتمد الإداري + المراجع العلمي ومؤهله وتاريخه |
| `knowledge_claim_sources` | ربط ادعاء ↔ مصدر (+ موضع) |
| `ingredient_knowledge` | INCI، الأسماء العربية، المرادفات، الوظائف، ملاحظة التركيز (فقط إن ذكرها مصدر)، احتمال التهيج |
| `knowledge_relationships` | helps_with / avoid_combining / related_topic … |
| `knowledge_review_history` | كل انتقال، مع لقطة النص السابق؛ لا حذف |
| `knowledge_gaps` | مفتاح مفهوم فقط (لا نص الموظف) + عدد مرات الظهور |
| `knowledge_ingestion_jobs` | مهام البحث في الموصلات |
| `knowledge_retrievals` (CP06.2، موسّع) | الأدلة المكتشفة + نتيجة التحقق + حالتها |
| `knowledge_retrieval_log` | بصمة السؤال (لا نصه) + الادعاءات المستخدمة |
| `knowledge_connector_state` / `knowledge_cache` / `knowledge_settings` | القاطع والعدادات، التخزين المؤقت، مفتاح البحث الخارجي |

لا جداول مكررة: `knowledge_retrievals` غير المستخدم في CP06.2 أُعيد استخدامه بدل إنشاء `knowledge_evidence`.

## 4. حالات المعرفة ومن يغيّرها

```
discovered → extracted → pending_review → approved → published
                               │             │           └→ needs_update / superseded
                               └→ rejected   └→ needs_update / rejected
```
- الاعتماد والنشر: **المدير فقط**، ويتطلبان مصدرًا واحدًا على الأقل؛ الرفض و«يحتاج تحديثًا» يتطلبان سببًا.
- `review_level`: `none` → `administrative` (اعتماد المدير) → `qualified_scientific` (يسجّله المدير مع اسم المراجع ومؤهله — التطبيق لا يتحقق من الشهادة، ويقول ذلك).
- التعديل لا يمحو: نسخة جديدة `@v2` في `pending_review`، والقديمة تبقى قابلة للاستخدام حتى اعتماد الجديدة ثم تصبح `superseded`.

**ما الذي يظهر في الإجابة:**

| الحالة | يُستخدم؟ | الوسم الظاهر |
|---|---|---|
| approved/published + qualified_scientific | نعم | «راجعه مختص مؤهل» |
| approved/published | نعم | «معتمد إداريًا — لم يراجعه مختص مؤهل بعد» |
| pending_review **وأصله البذرة المنسقة** | نعم (سلوك CP06.2) | «مرجع منظم لم يراجعه مختص مؤهل بعد» |
| أي شيء من الموصلات قبل الاعتماد | **لا** | — |

## 5. الخيارات المعمارية المقارنة (Phase 2)

| الخيار | الوصف | النتيجة |
|---|---|---|
| **A** | CP07 + SQLite FTS5/BM25 + نموذج محلي | الاسترجاع ممتاز دون نموذج؛ النموذج يضيف كلفة وخطأ (انظر تقرير النماذج) |
| **B** | CP07 + بحث مرخص على الإنترنت + قواعد محلية | منفّذ كمسار **نمو معرفي** فقط (يغذي المراجعة)، لا كمصدر إجابة مباشرة |
| **C** | CP07 + مكونات RAG (متجهات/رسم) + نموذج | مرفوض: لا تحسن مقاس على مجموعة من ~80 ادعاءً، ويتطلب نموذج Embeddings |
| **المختار** | **A دون نموذج افتراضيًا + B للنمو المنضبط**، والنموذج طبقة اختيارية معزولة | انظر `CP07_FINAL_INTEGRATION_DECISION.md` |
