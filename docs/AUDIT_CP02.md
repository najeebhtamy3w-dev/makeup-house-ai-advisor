## المعمارية الحالية مقابل المستهدفة، ومتى تصبح الترقية ضرورية
| الآن | المستهدف | محفّز الترقية |
|---|---|---|
| SQLite (ملف، كاتب واحد) | PostgreSQL | أكثر من نسخة خادم، أو استضافة بلا قرص ثابت، أو ≥ ~20 مستخدمًا متزامنًا بكتابات كثيفة، أو >~50,000 منتج مع بحث نصي متقدم |
| مسارات في ملف واحد | وحدات لكل مجال | عند إضافة مجال خامس أو ملف >500 سطر |
| استرجاع بمسح كامل | فهرسة FTS5 أو تصفية SQL مسبقة | >~50,000 منتج أو زمن مستشار >500ms |
| طابور في ذاكرة العملية (جدول DB + مؤقت) | عامل منفصل | عند إثراء عشرات الآلاف أو تعدد النسخ |
| واجهة وحدات ES | React/Next | فقط إن احتاج الفريق مكتبات مكونات؛ لا حاجة وظيفية الآن |
أي ترحيل بيانات يجب أن يمر بـ `scripts/backup.ts` ثم اختبار استعادة قبل التنفيذ.

## مراجعة HTML V2.3 (KEEP / IMPROVE / REMOVE / ADD)
* **KEEP:** الهوية الوردية/العنابية الهادئة، RTL، شريط سفلي للهاتف، «بطاقة مراجعة» قبل الحفظ، رسائل الصدق («محاكاة»، «غير موثق»).
* **IMPROVE (نُفذ):** الرئيسية → أفعال أولًا بلا إحصاءات غير قابلة للتنفيذ؛ المستشار → محادثة + أسئلة متابعة سياقية بدل أزرار ثابتة؛ المسح → إطار توجيه وحالات الإذن؛ المنتجات → فلاتر؛ التوفر → ثلاثة أزرار بدل `prompt()`.
* **REMOVE (نُفذ):** «تجربة سيناريو» بباركود وهمي، صفحة «الكتالوج العالمي» الميتة، تكرار البطاقات السريعة مع الشريط الجانبي، إحصاءات «منتجات مسجلة» بلا إجراء.
* **ADD (نُفذ):** محرك الإثراء + مراجعة المدير، الطابور، بطاقة توصية، إعادة المحاولة عند انقطاع الشبكة.
