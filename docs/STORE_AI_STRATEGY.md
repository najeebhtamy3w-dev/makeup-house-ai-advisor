# MAKEUP HOUSE — استراتيجية الذكاء الاصطناعي لموقع البيع والولاء
### (الموقع + Claude + واتساب الأعمال) — وثيقة مرجعية للتنفيذ المرحلي

> **النطاق:** هذه الوثيقة خاصة بموقع البيع والولاء **المستقل**. لا تعتمد على برنامج المستشار العلمي الموجود في هذا المستودع ولا ترتبط به.
> **الحالة:** توصيات للتنفيذ على مراحل، والأرقام فيها افتراضات تُضبط بعد القياس الفعلي. ليست أسعارًا معتمدة.

---

## 0. الخلاصة في سطور

1. **أقوى فكرة ماليًا ليست في قسم الأعضاء، بل في واتساب:** موظف مبيعات ذكي يرد على «متوفر؟ وكم سعره؟» من كتالوج الموقع مباشرة، ويقترح بدائل، ويجهز الطلب للموظف. في الحديدة تمر أغلب المبيعات عبر واتساب، أما الموقع في بدايته فلن يزوره عدد كبير.
2. **لا تقفل المستشار الأساسي خلف مهمات أو اشتراك.** كل سؤال تمنعه عن العميلة يعني بيعًا محتملًا ضاع. الأفضل أن نقفل **المكافآت والامتيازات الإضافية**.
3. **الأربعة عشر محركًا هي في الحقيقة محرك واحد بأوضاع متعددة** (استشارة، ميزانية، مقارنة، هدية، إطلالة). نبني محركًا واحدًا جيدًا، ونضيف ثلاثة محركات أخرى فقط على مراحل، ونؤجل الباقي أو نلغيه.
4. **فكرة «افتح البطاقة 3 أيام ثم تُقفل» تعمل ضدنا:** حين نسحب من العميلة شيئًا أعجبها نتركها مستاءة، ولن يتحول ذلك إلى دافع للعودة. نحتفظ بفكرة المهمات والمفاتيح، ونربطها بنقاط ومكافآت تبقى للعميلة ولا تُسحب منها.
5. **أعلى عائد خفي هو تقرير الطلب الأسبوعي:** ماذا سألت عنه العميلات ولم يكن متوفرًا. يبدأ تسجيله من اليوم الأول.

## 1. الربط الثلاثي: الموقع + Claude + واتساب الأعمال

### 1.1 البنية

```
            ┌──────────────────────────────┐
            │  قاعدة بيانات الموقع (مصدر الحقيقة) │
            │ منتجات · أسعار · توفر · أعضاء · نقاط │
            └──────────────┬───────────────┘
                           │  API داخلي (قراءة فقط للذكاء)
            ┌──────────────┴───────────────┐
            │        AI Gateway (خدمة مستقلة)       │
            │ أدوات محددة + سقف تكلفة + سجل محادثات │
            │ مزود قابل للتبديل (Claude / غيره)    │
            └──────┬───────────────┬────────┘
                   │               │
          ┌────────┴──────┐ ┌──────┴────────┐
          │ WhatsApp Cloud │ │ نافذة محادثة   │
          │ API (Meta)     │ │ داخل الموقع    │
          └────────┬──────┘ └──────┬────────┘
                   └──── صندوق وارد مشترك للموظفين (تحويل بشري) ────┘
```

**المبدأ الحاكم:** النموذج لا يخمّن ولا يكتب في قاعدة البيانات. يستدعي أدوات محددة (Tool Use)، والكود هو الذي يقرأ البيانات ويطبق القواعد.

### 1.2 الأدوات التي يُسمح للذكاء باستدعائها

| الأداة | الوظيفة | صلاحية |
|---|---|---|
| `search_products` | بحث مرن (أخطاء إملائية، لهجة، اسم الماركة بالعربي) | قراءة |
| `get_product` | السعر، الحجم، الصور، الرابط، حالة التوفر + وقت آخر تحديث | قراءة |
| `find_alternatives` | بدائل متوفرة بنفس الوظيفة / أرخص | قراءة |
| `get_member_summary` | رصيد النقاط والمستوى (رقم واتساب = هوية العميلة) | قراءة، للعضوة نفسها فقط |
| `create_order_draft` | تجهيز مسودة طلب **يؤكدها موظف** | كتابة مسودة فقط |
| `notify_when_available` | تسجيل طلب إشعار عند التوفر (بموافقة) | كتابة محدودة |
| `log_demand` | تسجيل منتج مطلوب غير متوفر | كتابة محدودة |
| `handoff_to_staff` | تحويل للموظفة مع ملخص المحادثة | — |

ما **لا يُسمح** به: تعديل سعر، أو منح نقاط، أو تأكيد طلب، أو وعد بخصم غير موجود في النظام، أو تقديم ادعاء طبي.

### 1.3 قواعد الرد

- السعر والتوفر يأتيان من الأداة فقط. إذا كان آخر تحديث للمخزون قديمًا يقول: «متوفر حسب آخر تحديث، وستؤكد لك الموظفة».
- إذا لم يجد المنتج: يعرض بديلًا متوفرًا، ويعرض الإشعار عند التوفر، ويسجل الطلب.
- يحوّل للموظفة في حالات: شكوى، أو تأكيد طلب، أو سؤال طبي، أو غضب، أو طلب العميلة صراحة.
- **عند رد الموظفة يدويًا تتوقف الآلة** في تلك المحادثة لمدة محددة حتى لا يتعارض الردان.

### 1.4 أسلوب الإطلاق الآمن (مهم)

| المرحلة | الوضع | المدة المقترحة |
|---|---|---|
| أ | **مساعد الموظفة:** الذكاء يكتب مسودة الرد، والموظفة تراجعها وترسلها | 2–4 أسابيع |
| ب | رد آلي على الأسئلة البسيطة (سعر/توفر/عنوان/مواعيد)، والباقي يذهب مسودةً للموظفة | حتى تستقر نسبة الأخطاء |
| ج | رد آلي كامل مع تحويل بشري ذكي | بعد القياس |

بهذا الأسلوب نحصل على بيانات حقيقية عن جودة الردود قبل أن نسلّم الآلة الرد على العملاء.

### 1.5 حقائق واتساب الأعمال التي يجب التخطيط لها

- نحتاج **WhatsApp Business Platform (Cloud API)**، فتطبيق واتساب بزنس العادي لا يدعم الربط البرمجي. ويلزم توثيق النشاط في Meta Business ورقم مخصص للخدمة.
- **الرد خلال 24 ساعة من آخر رسالة للعميلة** يدخل ضمن «نافذة خدمة العملاء» ويُعدّ الأرخص. أما **الرسائل التسويقية التي نبدأها نحن** (عروض، تذكير، إشعار توفر) فتحتاج قوالب معتمدة من Meta، ويُدفع عنها لكل رسالة، وتشترط موافقة العميلة المسبقة.
- ← لذلك نجعل التسويق عبر واتساب **بموافقة فقط وبعدد محدود**، ونعتمد على أن العميلة هي التي تبدأ المحادثة: رابط «اسألي المستشارة» على المنشورات والملصقات وكيس المشتريات.
- يجب التحقق من شروط Meta وتسعيرها الحالي لليمن وطريقة الدفع قبل الإطلاق. هذه الشروط تتغير.

### 1.6 الطلب بدون بوابة دفع

العميلة تطلب عبر واتساب أو الموقع ← مسودة طلب ← تأكيد الموظفة ← الدفع **عند الاستلام أو بتحويل محلي** (المحافظ والحوالات المحلية) ← تُحتسب النقاط **بعد التسليم فقط**.
هكذا يعمل البيع من اليوم الأول، دون انتظار بوابة دفع.

### 1.7 أكبر خطر تقني: دقة المخزون

إذا بيع المنتج في المحل ولم يُحدَّث على الموقع، فسيخبر الذكاء العميلة أنه متوفر.
- **حل البداية:** حالة توفر مبسطة (متوفر / كمية محدودة / نفد) مع وقت آخر تحديث، وتحديث يومي من الموظفة.
- **حل لاحق:** مزامنة مع النظام المحاسبي (المتكامل بلاس 6) إذا أتاح التصدير أو الربط، حتى لو كان تصدير ملف دوري.

### لماذا ألغينا أو أجلنا هذه الأفكار؟
- **الاتجاه الصحيح:** الأفكار التي تُنفَّذ أولًا تختصر الطريق بين السؤال والشراء. أما الأفكار المؤجلة فتطلب من العميلة جهدًا (إدخال حقيبتها، متابعة روتين يومي) قبل أن ترى أي فائدة.
- مشكلة الدقة: أداة ألوان ترشح درجة خاطئة تسبب مرتجعات وتضعف الثقة، وضررها أكبر من عدم وجودها.

## 3. المحرك الواحد بدل 14 محركًا

نبني **«مستشارة ميك أب هاوس»** كشخصية واحدة تعمل بأوضاع، وتعرض الواجهةُ الأوضاع أزرارًا سريعة:

| زر سريع في الواجهة | الوضع داخل المحرك |
|---|---|
| 🔎 أبحث عن منتج | بحث + سعر + توفر |
| 💬 اسألي عن بشرتك | استشارة ← منتجات متوفرة |
| 💰 معي ميزانية | بناء سلة ضمن مبلغ |
| 🎁 أبغى هدية | أسئلة: لمن/مناسبة/ميزانية ← طقم |
| 👰 عندي مناسبة | إطلالة من قوالب مراجَعة |
| ⚖️ قارني بين منتجين | مقارنة بيانات موثقة فقط |
| 📷 صوّري منتج | تعرّف ← مطابق أو بديل |
| ⭐ نقاطي ومكافآتي | قراءة من محرك الولاء |

**الفائدة:** موجّه نظام واحد، وأدوات واحدة، واختبارات واحدة، وتكلفة صيانة واحدة. كل وضع جديد يكلّف تعليمات إضافية، ولا نحتاج لبنائه نظامًا كاملًا جديدًا.

## 4. سياسة العضوية والمهمات: رأيي النهائي

### 4.1 تقييم فكرة «مراحل اللعبة» بدون مجاملة

| الجانب | الحكم |
|---|---|
| الفضول والتشويق بالبطاقات | ✅ فكرة قوية تسويقيًا |
| فتح البطاقة 3 أيام ثم قفلها | ❌ نسحب من العميلة ميزة أعجبتها، فتستاء بدل أن تتحمس |
| شرط «يدخل عدد من الرابط» | ❌ سهل التلاعب، والزيارات لا تساوي مبيعات |
| قفل المستشار الأساسي | ❌ يقلل المبيعات، لأن المستشار أداة بيع وليس هدية |
| فكرة المهمات + المفاتيح + المستويات | ✅ نحتفظ بها، لكن نربطها **بالمكافآت** لا **بالوصول** |

**الخطأ الجوهري في تصور GPT وفي الفكرة الأصلية:** كلاهما يعامل الذكاء الاصطناعي كأنه سلعة غالية نقننها. والواقع أن تكلفة الاستشارة النصية الواحدة بنموذج مناسب **أجزاء من السنت أو سنتات قليلة**، خاصة مع التخزين المؤقت للتعليمات (Prompt Caching)، والأرقام الدقيقة تؤخذ من صفحة أسعار المزود وقت التنفيذ. الشيء الغالي فعلًا هو **العميلة التي غادرت دون شراء**.

### 4.2 النموذج الذي أوصي به: «مفتوح للجميع، والمكافآت لمن يساهم»

**الطبقة المجانية للجميع (بدون شروط):**
- المستشارة الذكية على واتساب والموقع: السعر والتوفر والبدائل والاستشارة والميزانية والهدية.
- حماية التكلفة بسقف غير مرئي (مثلًا 30 رسالة يوميًا للرقم الواحد)، ثم تُحوَّل العميلة للموظفة. لا تظهر للعميلة أي «وحدات».

**المستويات تُكتسب بالشراء الفعلي (قواعد برمجية، لا ذكاء اصطناعي):**

| المستوى | طريقة الاكتساب (افتراضية) | الامتيازات |
|---|---|---|
| عضوة | التسجيل برقم الواتساب | نقاط على كل شراء، إشعار التوفر |
| فضية | مشتريات مؤهلة خلال 6 أشهر | حفظ الروتين والإطلالات، أولوية في الرد |
| ذهبية | مشتريات أعلى | عروض حصرية مبكرة، عينات مجانية، هدية عيد الميلاد |
| VIP | أعلى شريحة أو دعوة من الإدارة | حجز المنتجات الجديدة قبل الجميع، استشارة مباشرة مع خبيرة المحل، تغليف هدايا مجاني |

الامتيازات **ملموسة** (عينات، أولوية، حجز مسبق، تغليف). هذه أشياء تشعر بها العميلة فعلًا، وقيمتها في نظرها أعلى من «ميزة ذكاء اصطناعي إضافية».

**بنك المهمات يمنح نقاطًا أو مفاتيح، ولا يمنح «إذن استخدام مؤقت»:**

| المهمة | المكافأة | لماذا قابلة للتحقق |
|---|---|---|
| إكمال الملف (نوع البشرة، الاهتمامات) — مرة واحدة | نقاط | داخل النظام |
| أول شراء | نقاط مضاعفة | طلب مُسلَّم |
| **إحالة تنتهي بشراء مُسلَّم** — الطرفان يكسبان | نقاط كبيرة للطرفين | رمز شخصي + طلب مُسلَّم |
| تقييم صادق لمنتج **اشترته فعلًا** (لا يُشترط أن يكون إيجابيًا) | نقاط | مرتبط بطلب |
| المشاركة في استطلاع | نقاط قليلة | داخل النظام |
| اقتراح منتج غير متوفر ثم توفيره لاحقًا | نقاط + إشعار | سجل الطلب |
| تحدٍّ موسمي (رمضان/العيد/موسم الأعراس) | شارة + نقاط | حسب قواعد الحملة |

**تُلغى المهمات التالية:** «انشري الرابط» بلا نتيجة، وعدد النقرات، ولقطات الشاشة، والنشر اليومي.

**يبقى الجانب الممتع من فكرة اللعبة (Gamification):** لوحة بطاقات وشارات وشريط تقدم نحو المستوى التالي («باقي لك 3,000 ريال للذهبية»). والفرق أن البطاقة المفتوحة **تبقى مفتوحة** ولا تُسحب.

### 4.3 الاشتراك المالي

لا أنصح به الآن. الدفع الإلكتروني في السوق المحلي صعب، والعميلة لم تعرف الخدمة بعد.
**بديل أذكى للمستقبل:** «بطاقة VIP» تُباع **في المحل** أو تُهدى (مثلًا في المناسبات)، وتمنح مستوى ذهبيًا لمدة سنة. بهذا تتحول العضوية إلى منتج يُباع ويُهدى.

## 5. أفكار إضافية أراها أقوى من بعض الأربعة عشر

1. **رابط «اسألي المستشارة» في كل مكان**: QR على الكيس والفاتورة والرف والمنشورات، يفتح واتساب برسالة جاهزة. يكلّف تقريبًا لا شيء ويبني قاعدة عملاء على واتساب.
2. **تذكير إعادة الشراء الذكي**: نعرف تاريخ الشراء والحجم، فنرسل رسالة واحدة بموافقة العميلة قرب نفاد المنتج. عائده على المبيعات المتكررة من الأعلى.
3. **الروتينات والأطقم الجاهزة**: يقترحها الذكاء بناءً على الطلبات المتكررة، وتعتمدها الإدارة، ثم تُعرض كمنتج واحد بسعر واحد. هذا يرفع متوسط السلة.
4. **مساعد الموظفات (Staff Copilot)**: داخل صندوق الوارد يقترح الذكاء الرد والمنتج والبديل. يفيد من اليوم الأول ويقلل الاعتماد على خبرة موظفة واحدة.
5. **تقرير المشتريات الأسبوعي**: المنتجات الأكثر طلبًا وغير المتوفرة، والأسئلة المتكررة، والماركات الصاعدة، وساعات الذروة. قرارات الشراء من الموردين تُبنى على الطلب الفعلي.
6. **تقويم مواسم الحديدة**: رمضان، والعيدين، وموسم الأعراس، والعودة للمدارس. حملات موسمية جاهزة تديرها المستشارة («تجهيز عروس» و«هدية العيد»).
7. **مسار هدايا للرجال عبر واتساب**: رسالة واحدة («أبغى هدية لزوجتي بـ 20 ألف») تنتهي بطقم مغلف جاهز للاستلام. هذه شريحة لا تزور الموقع أصلًا.

## 6. خارطة التنفيذ داخل موقع البيع والولاء

### المرحلة 0 — الآن، أثناء بناء الموقع (رخيص الآن ومكلف لاحقًا)
تجهيز «AI-Ready» في نموذج البيانات فقط، دون أي ذكاء اصطناعي بعد:
- [ ] جدول منتجات بحقول منظمة: الفئة، نوع البشرة، المشكلة، اللمسة، الحجم، السعر، `stock_status`، `stock_updated_at`، الرابط، الصور.
- [ ] **أسماء بديلة** لكل منتج: الاسم العربي، والنطق الشائع، والأخطاء الإملائية (مثل «لاروش / لا روش / LRP»).
- [ ] رقم الهاتف معرّف أساسي للعضوة (يتوافق مع واتساب).
- [ ] جداول: الطلبات (مع حالة «مُسلَّم»)، والنقاط (دفتر حركات)، ورموز الإحالة، وطلبات الإشعار، و**سجل الطلب غير المتوفر**.
- [ ] API داخلي للقراءة: بحث منتج، ومنتج واحد، وبدائل، وملخص عضوة.
- [ ] سجل أحداث (Event Log) لكل بحث وطلب، ومنه نقيس لاحقًا.

### المرحلة 1 — موظف المبيعات الذكي
- [ ] AI Gateway + الأدوات في 1.2 + سقف تكلفة يومي/شهري + تنبيه.
- [ ] واتساب Cloud API + صندوق وارد للموظفات + إيقاف الآلة عند الرد البشري.
- [ ] الإطلاق بأسلوب 1.4 (مسودات ثم آلي جزئي).
- [ ] نفس المحرك كنافذة محادثة في الموقع.
- [ ] تقرير الطلب الأسبوعي.
- **مؤشرات النجاح:** زمن الرد، ونسبة المحادثات التي انتهت بطلب، ونسبة التحويل للموظفة، وأخطاء السعر والتوفر (الهدف صفر).

### المرحلة 2 — الولاء والنمو
- [ ] النقاط والمستويات (قواعد برمجية) + الاستعلام عنها عبر واتساب.
- [ ] الإحالة المزدوجة المشروطة بشراء مُسلَّم + منع الإحالة الذاتية والتكرار.
- [ ] أوضاع: الميزانية، والهدية، والمقارنة، والتعرف بالصورة.
- [ ] أخبريني عند التوفر + تذكير إعادة الشراء (قوالب معتمدة وموافقة).
- **مؤشرات:** معدل الشراء المتكرر، وتكلفة اكتساب العميلة بالإحالة، ومتوسط السلة.

### المرحلة 3 — نادي الجمال
- [ ] لوحة البطاقات والشارات وشريط التقدم (Gamification بلا سحب).
- [ ] حفظ الروتين والإطلالات للمستويات الأعلى.
- [ ] قوالب «اصنعي إطلالتك» مراجَعة من خبيرة.
- [ ] الأطقم الجاهزة وحملات المواسم.

### المرحلة 4 — بعد ثبوت الأرقام
- [ ] المكونات (بعد مراجعة مختص)، والاكتشاف المخصص، والحقيبة المعبأة تلقائيًا.
- [ ] الربط مع المتكامل بلاس 6.
- [ ] إعادة دراسة AR والألوان عبر مزود جاهز إذا ثبت الطلب.

## 7. ضوابط لا نتنازل عنها

- لا سعر ولا توفر إلا من قاعدة البيانات، ويظهر مع كل معلومة وقت آخر تحديث.
- لا نقاط ولا مستويات ولا خصومات تُحسب بالذكاء الاصطناعي. هذه قواعد برمجية فقط.
- لا ادعاءات طبية أو علاجية، والحالات الجلدية تُحال إلى مختص.
- لا رسائل تسويقية بدون موافقة صريحة، مع إمكانية الإيقاف بكلمة واحدة.
- لا حفظ للصور إلا بموافقة، مع حذف تلقائي.
- مزود الذكاء قابل للتبديل من الإعدادات دون إعادة بناء الموقع.
- سقف إنفاق يومي وشهري، وعند تجاوزه يتحول النظام تلقائيًا إلى وضع «تحويل للموظفة» ولا يتوقف البيع.
