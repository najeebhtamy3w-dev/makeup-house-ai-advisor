# CP06.2 — Phase 1: التنقل وحماية التعديلات (Gate 1)

**قرار البوابة 1: ناجحة.** الحالة: IMPLEMENTED · TESTED. ليست DEPLOYED (النشر موقوف على قرار L1). ليست VERIFIED ON STAGING.

## ما نُفذ

| المطلب (القسم 14) | التنفيذ |
|---|---|
| 1. زر رجوع ظاهر | رأس شاشة تعديل المنتج فيه زر «← منتجات» (أو «رجوع» إن فُتح المنتج من شاشة أخرى) |
| 2. الرجوع للسياق السابق | يُحفظ المسار الذي فُتح منه المنتج (القائمة، المسح، المستشار…) ويعود إليه |
| 3. حفظ المرشحات والموضع | البحث والمرشحات محفوظة سابقًا؛ أُضيف استرجاع الصفوف المحمّلة («عرض المزيد»، حتى 300) وموضع التمرير |
| 4. كشف التعديلات غير المحفوظة | حارس واحد لكل طرق الخروج: زر الرجوع، «إلغاء»، الشريط السفلي، Back/Forward في المتصفح، الروابط، إعادة التحميل/الإغلاق |
| 5. حفظ والخروج / تجاهل والخروج / متابعة | نافذة بثلاثة خيارات؛ Esc أو اللمس خارجها = متابعة (لا فقدان بيانات)؛ فشل التحقق عند «حفظ والخروج» يبقيك في الشاشة مع إظهار الخطأ |
| 6. منع الحفظ المكرر | حفظ واحد مهما تكرر الضغط أو Enter أثناء الإرسال؛ الضغط على «حفظ» ثم «رجوع» فورًا ينتظر الحفظ ثم يخرج بلا سؤال |
| 7. تنقل المتصفح | زر Back يُعترض ويبقى العنوان على المنتج أثناء السؤال |
| 8. منع تداخل الشريط السفلي | أزرار الحفظ فوق الشريط السفلي (مُختبر)؛ «حذف» نُقل من شريط الحفظ إلى قسم مستقل أسفل النموذج (للمدير فقط) |
| 9. متصفح الهاتف | مُختبر في Chromium بعرض 360 و390 بكسل |
| Android Back | **لم يُنفذ** (ممنوع في هذه المرحلة) |

**قرارات هندسية موثقة:**
- **شاشة إضافة منتج جديد لم تُغيَّر:** مغادرتها تحفظ المسودة على الجهاز وتستعيدها (سلوك CP05.3 المعتمد)، فلا يُسأل المستخدم هناك؛ زرها يبقى «منتجات» كما في التصميم المرجعي.
- **الشريط السفلي يبقى في شاشة التعديل** (سلوك CP05.3 المعتمد ومُختبر)؛ الحارس يمنع المغادرة الخاطئة عبره.
