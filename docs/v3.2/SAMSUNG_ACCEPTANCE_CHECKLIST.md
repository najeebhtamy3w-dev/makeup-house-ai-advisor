# قبول Samsung Galaxy S22 Ultra — V3.2 هندسي

الحالة الابتدائية لجميع اختبارات الهاتف أدناه **NOT TESTED**. لا اتصال فعلي موثق بالجهاز ولا قبول إنتاجي. الهدف اختبار نسخة معزولة تحمي التطبيق الدائم؛ نجاح Host أو المتصفح لا يملأ هذا السجل.

## حماية النسخة الحالية والتثبيت

1. لا تحذف النسخة الدائمة ولا تثبت Debug بهويتها فوقها. احتفظ بنسخة MHBAK2 مشفرة حديثة وكلمة مرورها محليًا خارج المحادثة، وتحقق من إمكانية استعادتها في بيئة اختبار قبل أي تحديث دائم. استخدم بيانات اصطناعية للاختبار، لا معلومات عميل حقيقية.
2. لا تبدأ قبل تسلم APK موجود فعلًا وmanifest تسليم وبصمته النهائية. قارن SHA256 محليًا. ملف Unsigned لا يثبت مباشرة؛ لا تحاول تجاوز فحص Android للتوقيع.
3. نسخة Debug المعدة لهذا الاختبار يجب أن تُظهر applicationId=`com.makeuphouse.advisor.engineering` وversionName=`3.2.0-dev.1-test`؛ النسخة الدائمة تبقى `com.makeuphouse.advisor`. تحقق قبل التثبيت بأداة aapt/apkanalyzer أو وثيقة الفحص المرافقة، ولا تعتمد على اسم الملف وحده.
4. ثبّت النسخة المعزولة وافتحها. يجب أن تظهر كتطبيق منفصل، وأن تظل منتجات وحسابات وصور التطبيق الدائم سليمة. لا تنقل بيانات حقيقية لها إلا بقرار واضح ونسخة مشفرة وتخزين آمن.
5. التوقيع الدائم خطوة لاحقة منفصلة بمالك المفتاح فقط. أدخل كلمة المرور في الطرفية المحلية، لا في المحادثة. الشهادة المطلوبة: `B5:1B:F9:B0:42:27:7C:F4:FD:0C:36:83:7C:5A:93:D7:7C:B6:73:FE:B1:C6:EE:9E:57:BD:60:26:50:4D:63:86`. لا مفتاح بديل ولا uninstall لتجاوز عدم التطابق.

## هوية الجهاز وإعداد التجربة

سجل:طراز الجهاز الفعلي، chipset (Snapdragon/Exynos كما يعرضه النظام/أداة موثوقة دون افتراض)، Android وOneUI وWebView، RAM المتاحة، التخزين الحر، حرارة الغرفة وحالة الشحن. لا تشغّل تطبيقات ثقيلة في الخلفية. سجل اسم APK وبصمته، commit المصدر، model_id/hash، وحجم context والخيوط إن توفرت.

النموذج المرجعي2B/Q4_K_M حجمه1,280,835,840بايت؛ تحقق من وجود مساحة إضافية للتنزيل المؤقت والتثبيت والبيانات. لا يثبت هذا الرقم استهلاك RAM. لا تثبت وزن4B تجريبيًا بدل manifest المعتمد من واجهة الموظف. تنزيل الوزن قرار مدير صريح، وليس تلقائيًا.

## القياسات والتشخيص

سجل على الأقل5محاولات بعد بدء بارد و5بعد تحميل مستقر لكل مهمة مناسبة:load time،TTFT إن سجله runtime،total latency،tokens/s،زمن الأدوات،زمن الإلغاء،الذاكرة الفعلية المتاحة/Peak PSS إن أمكن،حرارة/thermal status،تغير البطارية خلال مدة معلومة. افصل تهيئة KDF/تنزيل النموذج عن inference. لا تعلن GPU/NPU من توفر العتاد؛ يلزم log لتفعيل backend فعلي.

أدوات اختيارية على حاسوب المالك عند تفعيل USB debugging بموافقته:

```sh
adb shell getprop ro.product.model
adb shell getprop ro.soc.model
adb shell dumpsys meminfo com.makeuphouse.advisor.engineering
adb shell dumpsys battery
adb shell dumpsys thermalservice
```

قد تختلف صلاحيات أو أسماء حقول Android؛ احتفظ بالقيم المتاحة وحدودها. لا تشارك logcat كاملًا قبل تنقيحه؛ قد يحتوي بيانات أخرى. سجل diagnostic provenance دون نصوص العملاء أو كلمات المرور. تقرير المدير يجب أن يفرق generative_first/retry وclarification وevidence_selection وFallback والإحالة، ولا يحتسب مجرد model_invoked نجاحًا استدلاليًا.

لا توجد حدود أداء هاتف نهائية مقاسة حاليًا؛ يجب تحديد حد مناسب ومسبق مع مدة المهمة ونوعها قبل قبول الجهاز، لا اختيار حد بعد رؤية النتيجة. للسلامة:فقد بيانات/خرق حرج/مصدر أو منتج مختلق في حالات القبول=رفض. تأخر الرد لا يبرر تجاوز التحقق العلمي.
