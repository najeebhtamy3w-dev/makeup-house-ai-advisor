# صيغة الأدوات الأصلية Qwen — PoC V6.4 معزول

**التنفيذ:** سؤالان جديدان، ثلاثة استدعاءات Native فعلية. استُخدم قالب `tokenizer.chat_template` المستخرج من وزن2B المتحقق ببصمته، ورُسم عبر Jinja2 مع تعريفات الأدوات الحقيقية. لم يُعدل مصدر الإنتاج أو Runtime. لا Holdout ولا إجابات نهائية محفوظة.

تعرض الأداة ثلاث وظائف قراءة محددة: قدرات التطبيق، الأدلة المحلية، وسياق المحادثة. Parser يقبل أسماء ومعاملات محددة فقط، يرفض DTD/Entities والتداخل والمعاملات الزائدة، ويحد التنفيذ بأداتين وثلاث محاولات نموذج. نتيجة الأداة الفعلية تعاد داخل `<tool_response>` وفق القالب الأصلي. الأدلة العلمية تبقى بحالة مراجعتها الأصلية.

| الحالة | اختيار الأداة | النتيجة النهائية | القبول |
|---|---|---|---|
| موظف جديد يسأل عن المساعدة وحدودها | اختار `get_system_capabilities` فعليًا في14رمزًا، ونُفذت الأداة وأعادت5حقائق | جواب عربي مرتبط نسبيًا بالقدرات والحدود، لكن بلا معرفات استشهاد مطلوبة | PARTIAL لاختيار أداة واحدة؛ FAIL للجواب المتحقق |
| اختلاف احتياج الخد والأنف مع لسع العطر | لم يستدع أداة رغم الحاجة للأدلة | اخترع تفسيرًا أن الأنف أكثر تعرضًا للأكسدة والتشقق بالأكسجين، واقترح فئات منتجات غير مسندة | FAIL علميًا؛ لا يُعرض كنصيحة |

التحقق المستقل في `validate_xml.mts` يستخدم المعرفات المرصودة فقط و`fidelityCheck` الحالي عند minSupport=0.5 و`outputViolations`. **0/2 أجوبة نهائية مقبولة.** نجاح استدعاء أداة واحدة لا يثبت جودة الحوار أو الاستدلال العلمي.

## القرار

صيغة XML الأصلية أظهرت فائدة محدودة في اختيار أداة القدرات مقارنة بخطط JSON الفاشلة، لكنها لم تضمن الاسترجاع العلمي أو إسناد الإجابة. **لا نعتمد المسار الحر في الإنتاج ولا نخفف التحقق.** يمكن اختبار تسليم الإجابة نفسها عبر وظيفة منظمة ذات معرفات محددة، لحسم مشكلة Serialization؛ يبقى ذلك تجربة معزولة قبل أي دمج.

المحاولة الأولى توقفت في Harness قبل تشغيل النموذج لغياب Jinja2؛ احتُفظ بالسجل. لم تكن خسارة استدلال. ثبتت Jinja2 3.1.6 وMarkupSafe3.0.3 في مسار أدوات معزول بعد التحقق من عدم وجودهما في بيئة النظام أو Primary Runtime. لم يُضافا إلى اعتماديات التطبيق.
