# اختبار تسليم الإجابة كأداة XML — V6.4

الحالة: **4 استدعاءات Native حقيقية، أداتا قراءة فعليتان، صفر استدعاء تسليم صالح، 0/2 إجابات نهائية مقبولة**. لا تعديل للإنتاج ولا تخفيف للسلامة.

## الفرضية المحددة

أظهرت التجربة السابقة أن Qwen2B قد يستدعي أداة القدرات بصيغة XML الأصلية لكنه يهمل الاستشهادات داخل النص الحر. جرى اختبار هل يستطيع تمرير الإجابة وIDs عبر معاملات دالة `submit_application_response` بدل كتابة `[id]` داخل النص. هذه الدالة ليس لها أثر حفظ أو تعديل؛ هي واجهة تحقق للإجابة فقط.

تعريف الدالة يطلب `text` و`fact_ids`، ويحدد IDs المرصودة فعليًا بعد استدعاء أداة القدرات. المخطط يرفض معرفًا غير مرصود أو نصًا يتجاوز700حرف، ويستخدم بعد التسليم الدالة الحالية `fidelityCheck` عند0.5 لكل جملة، مع IDs التي اختارها النموذج نفسه فقط و`outputViolations`. لم تُصنع أو تُستنتج IDs لإكمال أي إجابة.

## النتائج الفعلية

| الحالة الجديدة | قراءة الحقائق | مخرجات ما بعد القراءة | الحكم |
|---|---|---|---|
| شرح الاستفادة للموظف وحدود المساعدة | استدعى النموذج `get_system_capabilities` فعليًا؛ أعادت الأداة خمس حقائق | نص عربي عادي رغم أن الأداة المتاحة للتسليم هي `submit_application_response` | FAIL: لم يستدع الدالة ولم يرسل fact_ids |
| متابعة عن تذكر زبونة اليوم عند العودة غدًا | استدعاء فعلي ثانٍ لأداة القدرات؛ السياق السابق من مخرجات النموذج الحقيقية موجود | أعاد شرح القدرات والحدود العام؛ لم يناقش الذاكرة أو الغد ولم يستدع دالة التسليم | FAIL: تجاهل مقصد المتابعة وعقد التسليم |

القراءة الناجحة لا تعني استشارة مكتملة. فحص Fidelity النهائي لم يُشغّل على Text/IDs غير موجودين؛ سبب الفشل سابق له وهو `EXACTLY_ONE_FUNCTION_REQUIRED`. النص الخام لم يُحوّل إلى استدعاء مصطنع ولم يُعرض كإجابة متحققة.

## القرار

لا يوجد دليل يبرر اعتماد مسار XML للتسليم النهائي أو تجاوز مسار التحقق. صيغة XML الأصلية مفيدة كدليل جزئي على قدرة استدعاء أداة، لكنها لم تحل اتباع عقد الإجابة أو استيعاب المتابعة في هاتين الحالتين. تبقى Gate02 غير مجتازة وGate03 غير مثبتة. هذه آخر تجربة معزولة لهذه الفرضية؛ لا نعيد مقارنات2B/4B/Phi أو Prompt المختصر بلا سبب مختلف.

الحدود: Host CPU فقط، Greedy الحالي،256رمزًا لكل استدعاء، مجموعتان تطويريتان وليستا Holdout ولا مراجعة عربية/علمية مؤهلة. لا Samsung أو Android/JNI أو قياس بطارية/حرارة.

## الملفات

- `results/cases-before-evaluation.json`: الأسئلة والتوقعات المجمدة قبل التقييم.
- `results/raw-responses.jsonl`: المطالبات والمخرجات والمقاييس الأربعة كاملة.
- `results/cases-results.jsonl`: نواتج الأدوات والسياق الفعلي المستخدم.
- `validation-results.json`: الفصل بين نجاح القراءة وفشل التسليم.
- `check_submission.mts`, `probe_submit.py`: القيود والتحقق القابلان للمراجعة.
- `run.log` / سجل المحاولة السابق إن كان موجودًا: خطأ Harness سابق للاستدلال محفوظ؛ لا يُحتسب فشلًا للنموذج.
