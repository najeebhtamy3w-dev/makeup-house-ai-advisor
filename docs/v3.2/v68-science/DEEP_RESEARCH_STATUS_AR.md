# V6.8 — البحث متعدد الفهارس: تنفيذ فعلي محدود، لا قبول علمي نهائي

## ما نُفذ

الملف الجديد `server/src/intelligence/deep-research.ts` يضيف `runDeepResearch` بوصفه أداة اكتشاف مصادر متعددة الفهارس، ويعيد استخدام `guardedSearch` الحالي: موافقة المدير/التعطيل، cache30يومًا، حدود المعدل واليوم، retries وcircuit breaker، ومخزن المراجعة `storeEvidence`. لا migration أو نسخة أخرى من المعرفة.

مصدران فعليان: PubMed عبر الموصل الموجود، وEurope PMC API عبر موصل جديد يطلب `resultType=lite` و`pageSize=5` ويقبل سجلات MED فقط. النتائج Bibliographic Metadata، لا abstracts أو نصوص كاملة. لا تُستنتج نتائج الدراسات أو سلامة المكونات من عنوان المقالة. معلومات المصدر لا تمنح مراجعة بشرية، ولا تتحول إلى ادعاءات معتمدة.

المدخل هو **مفاهيم علمية معروفة كاملة فقط**، لا نص محادثة أو بيانات زبون/مخزون. يتم تحويل أسماء INCI ومرادفاتها ومفاهيم محددة إلى صيغ عامة ثابتة. المفهوم غير المدعوم يرفض الطلب قبل الاتصال؛ لا يُرسل النص الخام حتى جزئيًا. هذا قيد خصوصية، وليس فهمًا توليديًا بديلًا. تفسير السؤال واختيار المفاهيم مسؤولية النواة التوليدية قبل استدعاء الأداة.

الحدود: استعلامان كحد أقصى، مصدران لكل استعلام، ثمانية طلبات HTTP فعلية، مهلة إجمالية18ثانية افتراضيًا/30ثانية أقصى. الإلغاء/انتهاء المهلة يشمل انتظار جسم الرد حتى لو لم يلتزم المزود بالإلغاء؛ الإلغاء تعاوني ولا يُعد ضمانًا realtime على Android. لكل مصدر حالة مستقلة، وتُحفظ النتائج السابقة عند تعذر مصدر آخر.

تُدمج معرفات PMID/DOI، مع عد كل Publication مرة واحدة عند ظهوره في الفهرسين. ظهور الدراسة نفسها في PubMed وEurope PMC ليس دليلين مستقلين. DOI واحد مع PMID مختلف لا يدمج خفية؛ يسجل تعارض هوية. اختلاف العنوان/السنة يسجل تعارض Metadata، **لا تعارض نتائج علمية**. `study_independence` و`retraction_status` و`conflict_analysis` غير مقيمة. درجة `metadata_quality` ليست ثقة بصحة نتائج الدراسة.

## عقد الربط للنواة

```ts
runDeepResearch(db, {
  concepts: ['niacinamide', 'sensitive skin'],
  domain: 'skin', // skin | hair | both
  max_queries: 2
}, { fetch, online, signal, timeoutMs: 18000 });
```

المخرجات: `status`, `concepts`, `calls` (مصدر/استعلام/حالة/cache)، `requests`, `stored`, `publications` بمعرفات وروابط ومصدر/سنة/حالة مراجعة وتعارض Metadata، `claims:[]`, `scientific_conclusions:[]`, `warnings` وحدود الاستنتاج. cache المحلي متاح دون شبكة فقط عند تفعيل ميزة البحث مسبقًا، ويظهر `offline_cached`؛ لا يُدّعى حدوث بحث جديد أثناء انقطاع الشبكة.

Root مسؤول عن ربط المصادقة والأداة بالمنسق/المحادثة؛ هذا الوكيل لم يعدل tools/routes/orchestrator/contracts/migrations. لا يوجد إدماج مباشر لـPaperQA2 أوGPT Researcher أوAviary؛ هذا بديل وظيفي صغير للبحث والتطبيع والتكرار والمراجعة. لا يدّعي معادلة Deep Research الكامل أو agents ذكية مستقلة.

## الأدلة الفعلية

- `focused-tests.log`:10/10 اختبارات PASS بموصلات فعلية وHTTP fixtures. تثبت الخصوصية/التعطيل/الهوية/cache/الإلغاء والحالات، **لا جودة علمية أو نجاح مزود حي**.
- `typecheck.log`: TypeScript PASS وقت الاختبار. قد تغيّر المسارات الأخرى المصدر بعد ذلك؛ الاختبارات النهائية مسؤولية المنسق الرئيسي.
- `live-public-probe.json`: استدعاء Host حقيقي بمفهوم عام `niacinamide`، دون بيانات شخص أو محل. نجح PubMed في إرجاع خمسة سجلات Metadata حقيقية وحُفظت للمراجعة؛ لم يكمل Europe PMC ضمن مهلة15ثانية. الحالة الفعلية `cancelled_or_deadline`، لا نجاح متعدد المصادر. التواريخ والروابط ومعرفات PubMed في الملف. استخدم هذا المثال نسخة metadata قبل إعادة تسمية عداد Publication؛ لا يُعد قياسًا علميًا.

لم تُجرَ استشارة علمية مولدة أو دراسة نتائج abstracts، ولا اختبار Samsung/CORS/وضع الطيران أو قبول الوكيل من واجهة المستشار. لا `PASS` للقبول النهائي.

## مصادر تقنية أولية فُحصت

- Europe PMC official RESTful API: https://dev.europepmc.org/RestfulWebService — JSON وresultType lite/core ومسار الإنتاج موثقة. تم فتحها فعليًا26نوفمبر2026. لم تُنسخ نصوص المقالات.
- موصل NCBI الموجود بالمشروع يستعمل E-utilities. مرجع NCBI: https://www.ncbi.nlm.nih.gov/books/NBK25501/ — ظهر reCAPTCHA عند فحص الصفحة؛ لم يُدّعِ اجتيازها. لم يُغيَّر parser PubMed الموجود أو ترخيص المحتوى.

لا مدفوعات، ولا خدمة LLM خارجية، ولا صور/مخزون مرسل، ولا إجراء متعلق بالتوقيع.
