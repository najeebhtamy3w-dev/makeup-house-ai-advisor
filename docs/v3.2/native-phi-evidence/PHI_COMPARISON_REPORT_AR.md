## قالب المحادثة — تحقق فعلي لا تمرير قالب Qwen إلى Phi

الـGGUF يعلن architecture=phi3 وtokenizer=gpt2/pre=gpt-4o، ويدعمه llama.cpp المثبت. قورنت `tokenizer.chat_template` المضمنة بتكوين Microsoft الأصلي. فحص التطابق الحرفي الأول رفض فرقًا وحُفظ فشله؛ تبين أن الأصل يضيف eos_token فقط عندما add_generation_prompt=False، بينما التحويل حذف هذا الفرع غير المستخدم. بعد حذف هذا الفرع وحده يتطابق نص القالبين تمامًا.

الحالات المفحوصة كلها تستخدم add_generation_prompt=True ورسالتَي System/User دون tools داخل رسالة النظام. قالبها الصحيح:

`<|system|>…<|end|><|user|>…<|end|><|assistant|>`

استعمل Harness هذا القالب، وأزال فقط تحكم Qwen الخاص `/no_think` ومقدمة assistant think. لم يغيّر حقائق السؤال أو عقد المخطط أو يُضف إجابات متوقعة. لا Python من النموذج أو trust_remote_code أو أوامر خارجية مستخرجة من بطاقة النموذج. محاولة اعتماد Jinja2 تعذرت لعدم وجود الحزمة؛ لم تُثبت حزمة إضافية، واستُخدم Rendering مباشر للفروع البسيطة المفحوصة مع تحقق فرق القالب المحدد. السجلات محفوظة.

## النتائج الجديدة

نُفذت ثلاثة طلبات حقيقية على Host مع نفس binary؛ السؤالان الخامان نفس مدخلي مقارنة Qwen2B/4B السابقين، والثالث إعادة طلب المخطط المحفوظ مع تكييف Envelope فقط. هذه مجموعة تطوير صغيرة، وليست Holdout ولا قياسًا للهجة اليمنية لدى مختص.

| الحالة | Input/Output tokens | TTFT | Generation | النهاية |
|---|---:|---:|---:|---|
| التفريق بين وصف الشركة والدليل المستقل |81/107 |2.539s |12.279s |stop |
| جذور شعر تزيت وأطراف تتشابك/تتكسر وحساسية عطر |97/192 |2.606s |20.260s |length |
| مخطط سؤال القدرات |625/122 |20.198s |36.529s |stop |

تحميل النموذج6.183s. أعلى VmHWM مقاس أثناء الطلبات4,314,036kB، نحو4.11GiB لعملية Linux، لا PSS تطبيق Android. لم نقس Samsung أو حرارة/بطارية أو GPU/NPU.

**الملاحظة النوعية الهندسية:**

- جواب الدليل العلمي صاغ أمثلة افتراضية بعبارات «تم إجراء تجارب علمية موثوقة» بلا مصدر مسترجع، مع تعبيرات عربية ركيكة مثل «هذا الفاخر» و«وصف الشركة…مزعجًا». لا يُعرض على الموظف كإجابة علمية متحققة.
- جواب الشعر دخل تكرار «عطر مزيح» حتى بلوغ192رمزًا، ولم يقدم مناقشة متماسكة للجذور والأطراف. يُسجل length وفشل فائدة هذه العينة، لا استشارة مكتملة.
- المخطط صحيح JSON واختار `get_system_capabilities` فعلًا، لكنه علّم كل حقول النقص، ومنها pregnancy/reaction/skin/hair/product، رغم أن السؤال عن قدرات النظام، وأعاد السؤال بدل استيضاح مناسب. اختيار أداة صحيحة لا يمحو هذا الخطأ الدلالي.

النتيجة لا تثبت تفوق Phi على Qwen الحالي ولا تبرر ترقيته. كما لا تثبت أن العائلة عاجزة تحت جميع إعدادات Sampling: استُخدمت سياسة Greedy الحالية للمسار التشغيلي، ولم تُحسن معاملات كل نموذج منفصلًا. المقارنة ضيقة وتكشف إخفاقات فعلية، وليست درجة نهائية أو شهادة علمية/لغوية.

## المقارنة بالمرشحين السابقين

Qwen3.5-2B وQwen3.5-4B وPhi-4-mini كلها ولدت نصًا عربيًا فعليًا على Host؛ هذا يثبت Native inference فقط. في السؤال المركب ظهرت مشكلات صياغة/فهم وانقطاع عند الحد في المرشحين الثلاثة، وكانت Phi أشد تكرارًا في هذه العينة. استهلاك Phi و4B قريب من4GiB مقابل نحو1.83GiB لـ2B في قياس العملية السابق. لا تكفي هذه العينات لاختيار «أفضل عقل» للتطبيق أو تعميم سرعة على الهاتف.

الأولوية تبقى قبول المسار الرئيسي الحقيقي وخطته وقراره وإسناده مع أسئلة مستقلة وذاكرة وسلامة. لا يجوز تبديل اسم النموذج لإعلان إصلاح الذكاء، ولا احتساب Raw Diagnostic أو JSON صالح نجاحًا للاستشارة.

## الملفات وإعادة التنفيذ

- `results/raw-responses.jsonl`: كل prompts/text/metrics/ذاكرة ونتائج تحليل المخطط.
- `results/metadata.json` و`gguf-metadata.json` و`template-inspection.json`.
- `results-template-diff/` وسجلات run السابقة: فشل بوابة التطابق الحرفي الأول محفوظ.
- `probe_phi.py`: Harness معزول؛ يستدعي Host binary ويقرأ مدخلي Raw السابقين وطلب المخطط، لا Holdout.
- `SHA256SUMS.txt`: بصمات هذه الأدلة.
