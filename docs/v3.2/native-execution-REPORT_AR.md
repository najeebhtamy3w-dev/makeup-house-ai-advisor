# التنفيذ الأصلي للذكاء المحلي — أدلة جديدة وحدودها

26 نوفمبر2026. هذا تقرير مكوّن Native/Host، وليس تقرير قبول التطبيق أو Samsung.

## ما تغير فعليًا

- أضيفت allowlists typed إلى Native generate وHost session: `allowed_product_ids:number[]` و`allowed_claim_ids:string[]`، أقصى50 لكل منهما. تُرفض IDs الصفرية/الكسور/المفرطة وأسماء الادعاء الفارغة أو ذات محارف تحكم. تُقتبس قيم الادعاءات مرتين بأمان بصيغة JSON ثم GBNF، ولا تقبل API قواعد Grammar يكتبها المتصل.
- Grammar القرار والمنتجات يستعمل enums من هذه القوائم؛ القوائم الفارغة تُجبر المراجع والتوصيات والروتين والاستنتاجات المسندة على الفراغ، لا تعود إلى IDs عددية حرة. يبقى التحقق العلمي والتفويض في العامل مستقلين؛ enum صحيح لا يثبت ملاءمة أو صدقًا علميًا.
- Grammar يدعم intent `capabilities` والأدوات `get_system_capabilities` و`scientific_specialist` و`get_product_images`، وحقل specialist الاختياري skin/hair/inci/formulation/evidence، وresponse_segments الاختيارية مع الحفاظ على عقد القرار السابق.
- أضيف `diagnose` للمدير فقط عبر نفس فحص الدور الفعلي لكل استدعاء. يتلقى سؤالًا نصيًا، ويشغّل النموذج دون plan أو decision أو retrieval أو grammar أو validator أو fallback. الناتج يحمل `RAW_NATIVE_DIAGNOSTIC_NOT_CONSULTATION` و`validated:false`. مسار generate العادي ما زال يرفض task diagnostic، فلا يصبح هذا منفذًا للموظف إلى استشارات غير متحققة.
- التشخيص يعيد Input/Output Tokens وTTFT ووقت التحميل والتوليد وfinish_reason stop/length/cancelled/error. النص raw ليس مراجعة علمية ولا جواب موظف معتمدًا.
- حالة Native تفصل installed/active/loaded وverified/verified_sha256 وphase وlast_operation_error. ABI أعيدت كمصفوفة JSON فعلية. verified لا يصبح true إلا بعد فحص SHA حقيقي في العملية الحالية؛ false بعد إعادة تشغيل العملية لا يعني فسادًا مثبتًا.
- install يفحص النموذج الموجود الصحيح ويعيد الحالة بدل إعادة تنزيله. لا استبدال أو تنزيل تلقائي لأوزان سبق تثبيتها صحيحة.
- القدرات المعلنة صراحة text:true وvision:false لهذا التكامل؛ لا يوجد projector/vision execution في هذا GGUF/JNI الحالي.

## استعادة البيئة دون هدم التطبيق

لم يبقَ Cache للنموذج أو بناء Host أو CMake/Ninja في البيئة المتاحة. جُهزت المكونات المفقودة فقط خارج المشروع تحت `../toolchain/native-recovery/`:

- llama.cpp Commit `b1b770d90d94cad9e9ea5b993bdbc383a522fb28`؛ أعيد التحقق من SHA256 الأرشيف `ae8556670b17c25931cd39eb7c95617650eaf6091bbcff206750583ddde1acb4` قبل الفك والبناء.
- Host Release build ناجح لـmh-ai-session وmh-ai-poc وmh-ai-test وmh-ai-constraints-test. هذه ليست Cross-compilation Android أو تنفيذ Samsung.
- النموذج2B المعتمد سابقًا:1,280,835,840بايت، SHA256 `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`.
- النموذج4B البحثي:2,740,937,888بايت، SHA256 `00fe7986ff5f6b463e62455821146049db6f9313603938a70800d1fb69ef11a4`. استُؤنف تنزيله Range بعد انقطاع جلسة عند1.4GB بدل إعادة تنزيل الجزء الموجود. تم التحقق من الحجم والبصمة كاملين قبل التشغيل.
- لم يُغيَّر اختيار Installer من2B إلى4B، ولم توضع أوزان في Git/APK أو يُفعّل مزود مدفوع.

## تجربة عربية خام فعلية — 2B مقابل4B

استخدم `scripts/native-execution-probe.py` سؤالين جديدين في هذا الفحص التطويري، بميزانية192رمزًا لكل إجابة ونفس قالب Diagnostic. السؤالان لا يوجد لهما جواب محفوظ في الكود. ليست هذه Holdout نهائية ولا مراجعة لغوية/علمية مؤهلة. Raw task لا يستخدم Grammar؛ تغيرات Grammar بين بناء2B الأول وبناء4B لا تطبق على هذا المسار، والبصمة الفعلية لكل binary محفوظة.

| النموذج/الحالة | Input/Output Tokens | TTFT | Generation | النهاية |
|---|---:|---:|---:|---|
|2B — التفريق بين وصف الشركة والدليل |96/173 |1.287s |11.893s |stop |
|2B — جذور تزيت وأطراف تتشابك وتتكسر وحساسية عطر |110/192 |1.615s |13.042s |length |
|4B — السؤال العلمي نفسه |96/162 |3.733s |22.348s |stop |
|4B — سؤال الشعر نفسه |110/192 |4.241s |30.058s |length |

تحميل2B في التشغيل1.847s، و4B3.773s. VmHWM المقاس للعملية أثناء هاتين الإجابتين بلغ2B نحو1,917,628kB، و4B نحو4,290,080kB؛ هذه ذاكرة عملية Linux، لا PSS تطبيق Android. البيئة تطوير مشتركة، وليست تجربة حرارة/طاقة معزولة؛ لا تُستخدم فروق الزمن لإعلان معدل هاتف.

**الملاحظات النوعية الهندسية:** النص العربي تولد فعلًا في النموذجين، لكنه غير كافٍ لاعتماد الذكاء.2B كرر «مصبوغ» واستعمل عبارة غريبة «بشرية حساسة»، وانقطع جوابه الثاني عند الحد.4B أدخل «الساقط السريع» و«بسبب السقوط» رغم أن السؤال عن دهون الجذور وتشابك/تكسر الأطراف، واستعمل «لون الشعر (مكسور أم طبيعي)» و«متصنع (مكروم)». كما أن جوابه عن الاستقلال العلمي عمّم التمويل المحايد والتحكيم دون دليل مسترجع. لا أوصي بترقية4B بناءً على هذه العينة، ولا أصف2B بأنه اجتاز العلم أو اليمنية. يلزم اختبار النواة المتكاملة والتحقق المستقل ومراجعة مؤهلة.

الأدلة الخام تحت `native-execution-evidence/2b-raw-20261126/` و`4b-raw-20261126/`، بما فيها prompts/text/metrics وVmHWM وبصمات النموذج والثنائي. الإجابتان المقطوعتان مسجلتان length، لا تُحسبان استشارتين مكتملتين.

## عيب أداء حقيقي اكتُشف وصُحح

الاختبار العدائي ذي قوائم IDs الفارغة لم يختلق IDs في الحقول المنظمة، لكنه علق في whitespace: بدأ `selected_claim_ids:[` ثم ولد مئات TABs حتى384رمزًا وانتهى length خلال44.241s، ففشل JSON. أُبقي Raw الفشل في `2b-empty-allowlist-384/`، وفشل المحاولة الأقدم192رمزًا في السجل؛ Harness الأقدم لم يحفظ الاستجابة النهائية قبل فشل parsing، وهذه فجوة دليل موثقة وليست نجاحًا.

السبب: قاعدة ws غير محدودة تسمح باستمرار Padding عندما يمنع Grammar اقتراح الموديل. صُححت إلى أربعة محارف whitespace كحد أقصى عند كل حد بنيوي. هذا لا يخفف أي سياسة سلامة أو يبدل توقعات الاختبار.

إعادة نفس الاختبار بعد تغيير الفرضية/الكود:2B أنتج JSON صالحًا، والقوائم المقيدة بقيت فارغة،136رمزًا خلال14.589s، stop.4B اجتاز اختبار الحقول نفسه بـ103رموز خلال19.576s، stop.

**حد مهم:** النص الحر داخل clarification أعاد ذكر تعليمات الاختبار العدائية في2B. لذلك النجاح أعلاه يخص **حقول المعرّفات فقط**؛ ليس قبول أمان النص كله أو Grounding. يجب أن يرفض التحقق المستقل مثل هذا المحتوى قبل عرض استشارة. لا تسمح قوائم Native وحدها بادعاء منع جميع الهلوسة.

## الخطوة التالية

يشغّل الوكيل الرئيسي الواجهة الموحدة مع Host binary الحقيقي، ويمرر request allowlists إلى Native، ويقيس التخطيط والقرار والتحقق في الاستشارة الفعلية. تثبيت Runtime ونص عربي خام لا يكفيان لقبول المتطلبات. تحفظ واجهة المدير الفرق بين RAW diagnostic وبين الاستشارة المتحققة، وتبقى رؤية الصور/المسح خارج قدرات runtime الحالي حتى تنفيذ مسارها الحقيقي.
