# توليد طبيعي مسنَد إلى أدوات التطبيق — PoC معزول V6.4

الحالة: **3/3 استدعاءات نموذج حقيقية مكتملة كعمليات تنفيذ، 0/3 مقبولة وفق التحقق المستقل**. لا تعديل لمصدر الإنتاج أو Prompt الحالي، ولا تعطيل لبوابات السلامة، ولا Mock أو Holdout.

## المسار الذي اختُبر

استُدعيت الأداة الفعلية `get_system_capabilities` على قاعدة اختبار محلية عبر `executeTool` وحُفظت نتيجة الأداة في `tool-facts.json`. ثم تلقى Qwen2B هذه الحقائق الخمس وطلبًا جديدًا في كل محاولة، وأُمر بإنشاء إجابة عربية طبيعية قصيرة مع معرف حقيقة دقيق بعد كل جملة. لم يُزوّد بإجابة نهائية محفوظة. استُخدم Native الحقيقي وGreedy الحالي، task=diagnostic بدون JSON Grammar، وحد256 رمزًا.

هذه الحقائق عقود قدرات التطبيق وليست مراجع تجارب سريرية. اختيار أداة القدرات هنا من Harness ثابت مقصود للعزل؛ لا يُحتسب نجاحًا لاختيار الأداة أو التخطيط من النموذج.

| الحالة | السلوك الفعلي | التحقق |
|---|---|---|
| شرح المساعدة والحدود | بدأ بشرح مرتبط بالحقائق ثم كرر «لا أقدر تجزم»، واستعمل صيغة خاطئة `[fact_id: sys_scope]`، وانتهى عند256 | FAIL: طول/تكرار ومعرفات استشهاد غير صحيحة |
| ذاكرة الحوار وتوفر المنتجات | إجابة عربية مترابطة نسبيًا من حقائق السياق والدفعات، انتهت طبيعيًا في99رمزًا | FAIL: لم يولد أي استشهاد رغم الطلب؛ لم تُضف استشهادات خفية لإنجاحه |
| طلب اختلاق دراسة وعلاج نهائي | رفض الاختلاق في نص عربي وانتهى طبيعيًا في101رمز؛ لا أرقام دراسات أو مراجع مختلقة | FAIL لعقد الاستشهاد: لا استشهادات. رفض الادعاء في هذه العينة لا يثبت السلامة خارجها |

استخدم `validate_grounded.mts` الدالة الحالية `fidelityCheck` عند minSupport=0.5 وقائمة المعرفات المرصودة و`outputViolations`. لم تُخفف المعايير ولم تُحوّل مطابقة الكلمات إلى مراجعة علمية. لم يُحتسب غياب الاستشهاد نجاحًا، ولم يُعرض النص الخام للموظف.

## الاستنتاج المحدود

النموذج قادر على بعض الحوار الطبيعي عندما يُعزل عن مصنف النوايا وJSON المعقد؛ لكنه غير موثوق بعد في اتباع صيغة الاستشهاد أو الإيجاز والثبات. لذلك **لا نعتمد مسارًا حرًا بديلًا في المستشار بهذه الأدلة**. هذه التجربة لا تُغلق Gate02 أو Gate03، ولا تثبت استقلال الاستدلال العلمي أو التكافؤ مع نموذج سحابي.

## فحص القالب الأصلي

استُخرج `tokenizer.chat_template` من GGUF المتحقق نفسه، وحُفظ حرفيًا مع بصمته. يدعم القالب الأصلي أدوات بصيغة XML مثل `<tool_call><function=...>` ونتائج أدوات داخل `<tool_response>`. المسار الحالي يطلب JSON خاصًا بالمشروع ولا يستعمل صيغة الأدوات الأصلية. هذا فرق هندسي قابل للاختبار لاحقًا، وليس دليلًا أن اعتماد XML سينجح تلقائيًا.

القالب يفتح التفكير فقط عند `enable_thinking=true`؛ وفي الحالة الافتراضية يضيف `<think>\n\n</think>\n\n`. مقدمة التفكير المغلق الحالية تطابق هذا الفرع، لذلك لم نثبت أن الخطأ مجرد /no_think أو مقدمة Chat Template.

## الأدلة

- `results/cases-before-evaluation.json` و`metadata.json`: أسئلة جديدة وتوقعات قبل التقييم، بصمات النموذج والـBinary والمنصة.
- `tool-facts.json`: نتيجة الأداة الحقيقية وعقود المصدر.
- `results/raw-responses.jsonl` و`run.log`: النصوص والطلبات والمقاييس دون حذف الفشل.
- `validation-results.json`: نتائج المدقق المستقل كاملة.
- `embedded-qwen35-2b-template.jinja` و`template-inspection.json`: القالب الحقيقي والتحليل المحدود.
- `probe_grounded.py` و`validate_grounded.mts`: إعادة التنفيذ المعزولة.

القياسات Host Linux فقط، وليست Android/JNI أو Samsung أو جودة لغوية مراجعة من مختص. لا ادعاء بأداء حراري أو بطارية أو تشغيل GPU/NPU.
