# استمرارية البيانات والنسخ الاحتياطي عند 10,000 منتج — Host

الحالة: PASSED لاختبارَي NodeSQLite/WebCrypto الفعليين؛ NOT TESTED لـAndroid SQLite-WASM worker وSamsung وترقية APK الموقّع على الهاتف. البيانات كلها اصطناعية، ولا تثبت جودة الكتالوج الحقيقي.

## النطاق القابل لإعادة التنفيذ

```sh
node --no-warnings --import tsx --test tests/intelligence-backup-scale.test.ts
```

أنشأ الاختبار قاعدة SQLite حقيقية على القرص بملفات migrations001–009 الفعلية، ثم أضاف10,000منتج اصطناعي و10,000رمز داخلي نصي، مستخدمًا بالمعرف41 وصور PNG ثابتة صغيرة لثلاثة منتجات مع thumbnails، وسجل تدقيق وإثبات منتج مرتبطين بمعرفات مستقرة. مشغلات product_codes الفعلية تنشئ الرموز؛ يعدل الاختبار نوع رمز fixture إلى internal ويؤكد تملكه للمنتج. ليست الرموز باركودات تجارية حقيقية أو دليل صحة ماسح الكاميرا.

اختبر migration010/011 دون حذف أو إعادة إنشاء البيانات، وقارن SHA-256 لمحتوى كل صف مرتب بمعرفه قبل الترحيل وبعده، بما في ذلك users/products/product_codes/product_images/audit_log/evidence/knowledge_claims/knowledge_sources/knowledge_claim_sources/ingredient_knowledge/knowledge_relationships. تحقق PRAGMA integrity_check=ok وforeign_key_check فارغ. إعادة migrate لا تنفذ تغييرات جديدة. لا يتحول علم availability القديم تلقائيًا إلى دفعات مخزون؛ العدد صفر بعد ترحيل قاعدة قديمة دون دفعات.

## MHBAK1 القديم

استخدم seal/open من mobile/src/backup.ts على بايتات SQLite الحقيقية، ثم كتب الملف المفكوك وفتحه بواسطة Node DatabaseSync وشغّل010/011. تطابقت بصمة الملف الأصلي بعد فك التشفير وبصمات صفوف الجداول بعد الترحيل. رُفضت كلمة مرور خاطئة وتعديل البايت المشفر. لا يُغيّر الاختبار خوارزمية أو معاملات KDF الفعلية.

## MHBAK2 الحالي

بعد الترحيل أضاف الاختبار10,000دفعة مرتبطة بالمنتجات، و10,000سجل كتالوج عالمي draft ببيانات اصطناعية ومصدر example.invalid، وجلسة محلية مع ذاكرة revision3 وتشخيص صريح generative_invoked=false. بقيت هذه السجلات منفصلة عن المعرفة العلمية الحقيقية ولم تمنح اعتمادًا للكتالوج الاصطناعي.

أُنشئت لقطة متسقة بواسطة VACUUM INTO. استخدم BackupWriterV2/BackupReaderV2 الفعليين مع ملفات مفتوحة وقراءة متتابعة، إطار بيانات واحد في كل دورة، حد1MiB، وكتابة النص المفكوك مباشرة إلى ملف SQLite. طابقت SHA-256 اللقطة الأصلية، كما طابقت بصمات صفوف جميع الجداول القديمة والإضافات الجديدة. ظل المستخدم والصور والأدلة والتدقيق والمعرفات والعلاقات والذاكرة والتشخيصات والإعدادات محفوظة. إعادة migrate للنسخة الجديدة no-op.

تحقق رفض: كلمة مرور خاطئة، تبديل ترتيب الإطارات، تكرار إطار، تحريف ciphertext، تحريف رأس الأعداد الموثق، وإطار زائد بعد النهاية. دون إطار النهاية يبقى reader.done=false؛ يجب على مستهلك الاستعادة رفض النسخة غير المكتملة، ولا يُعد فك إطار جزئي نجاحًا.

تحتفظ النسخة بإعداد local_ai_metadata فقط (model_id وdesired_active)، ولا تضيف أوزانًا. لم ينشئ الاختبار ملفات نموذج أو يضمن وجودها بعد الاستعادة. لا توجد جداول weights/GGUF في schema المختبر. هذا فحص لمسار بايتات قاعدة البيانات وfixture الإعدادات؛ ليس تجربة ملفات التخزين الخاص بالنموذج أو تنشيط نموذج مفقود على Android.

## نتائج التشغيل المقاسة

تشغيل26نوفمبر2026، Node24.22.3 على Host، PASSED2/2، FAILED0، SKIPPED0:

| القياس | MHBAK1 | MHBAK2 |
|---|---:|---:|
| منتجات محلية اصطناعية | 10,000 | 10,000 |
| سجلات عالمية اصطناعية | 0 | 10,000 |
| دفعات اصطناعية | 0 | 10,000 |
| حجم SQLite بالبايت | 9,609,216 | 12,382,208 |
| حجم النسخة المشفرة بالبايت | 9,609,819 | 12,383,257 |
| إطارات البيانات | غير منطبق | 12 |
| أقصى plaintext chunk بالبايت | whole-file legacy | 1,048,576 |
| تشفير إطارات البيانات والنهاية ms | غير مفصول | 116 |
| فك إطارات البيانات والنهاية ms | غير مفصول | 91 |
| زمن الاختبار الكلي ms | 1,522 | 2,442 |

زمن اختبار MHBAK1 يشمل الإنشاء والتشفير والفك والتحقق والاختبارات العدائية. زمن MHBAK2 الكلي يشمل إنشاء البيانات والترحيل وبصمات الجداول واللقطة وفحوص التشويه؛ encryption_ms/decryption_ms لا يشملان إنشاء المفتاح PBKDF2 والرأس. القياسات ليست مقارنة سرعة مشفرة بين الصيغ؛ حمولة كل منهما مختلفة. التشويه وكلمات المرور عشوائيان، لكن أحجام الملف ثابتة في هذا fixture.

المخرجات الخام المتكررة قابلة للاستخراج من سطور V32_BACKUP_METRIC في stdout:

```json
{"kind":"MHBAK1_host_legacy","synthetic_products":10000,"sqlite_bytes":9609216,"encrypted_bytes":9609819,"elapsed_ms":1522,"migrations":["010","011"],"android":false}
{"kind":"MHBAK2_host_stream","synthetic_products":10000,"synthetic_global_products":10000,"synthetic_batches":10000,"sqlite_bytes":12382208,"encrypted_bytes":12383257,"data_frames":12,"max_plain_chunk_bytes":1048576,"encryption_ms":116,"decryption_ms":91,"elapsed_ms":2442,"android":false,"peak_memory":"NOT_MEASURED"}
```

Peak memory غير مقاس. فحص البصمة النهائية يقرأ الملف كاملًا على Host للاختبار، وMHBAK1 بطبيعته whole-file؛ لا تدّعي النتائج أن كامل اختبار التحقق محدود الذاكرة. مسار تشفير/فك MHBAK2 نفسه متتابع بإطار واحد، لكن لم يُقَس RSS أو حد الذاكرة الفعلي. لا توجد قياسات حرارة أو بطارية أو استجابة UI أو تجربة مرور10,000طلب API. ملفات SQLite المؤقتة والنسخ الاصطناعية تُحذف في finally؛ المصدر قابل لإعادة إنتاجها.

يبقى مطلوبًا قبول worker SQLite-WASM والاستعادة في التطبيق الفعلي، الصور الكبيرة، ضغط الذاكرة، انقطاع Android أثناء الاستعادة، وترقية التطبيق بالمفتاح الدائم وحفظ بيانات المستخدم الحقيقي. الاختبار هنا دليل استمرارية بيانات وتشفير Host فقط، وليس موافقة إنتاجية أو اختبار جهاز.
