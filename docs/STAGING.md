# نسخة Staging السحابية المحمية — النشر والتجربة من Samsung (بدون Windows)

> نسخة **تجريبية** فقط: تبدأ بقاعدة منتجات **فارغة**، وقد تُحذف كل البيانات عند أي إعادة تشغيل أو سكون (الخطة المجانية). ليست قاعدة بيانات المحل.

## ما الذي يُنشر
* حاوية واحدة (Dockerfile): خادم Node 22 + الواجهة + SQLite المدمجة، كمستخدم غير مميز `node`.
* `render.yaml` (Render Blueprint، الخطة **المجانية** `plan: free`).
* `MH_STAGING=1` يفعّل: شريط تحذير دائم، حساب موظف تجريبي اختياري، `noindex` على كل الردود، و`robots.txt` يمنع الفهرسة. **لا تُنشأ أي منتجات تلقائيًا** (أُزيلت المنتجات التجريبية في تصحيح CP05).
* `MH_ENRICH=obf`: البحث العالمي الحي في Open Beauty Facts (النتائج **مسودات** يراجعها المدير، ولا تُعتمد تلقائيًا).

## قيود الخطة المجانية في Render (تحقق منها عند التسجيل)
* القرص مؤقت: كل ما يُدخل يُحذف عند إعادة التشغيل أو إعادة النشر أو السكون.
* السكون بعد ~15 دقيقة بلا استخدام؛ أول فتح بعدها يستغرق ~1 دقيقة.
* 750 ساعة تشغيل مجانية شهريًا لكل حساب.
* **إذا طلب Render بطاقة دفع: توقّف ولا تدخلها** وأبلغنا (لن نستخدم خدمة مدفوعة).

## خطوات الربط من الهاتف (مرة واحدة، ~5 دقائق)
1. افتح من متصفح Samsung رابط النشر:
   `https://render.com/deploy?repo=https://github.com/najeebhtamy3w-dev/makeup-house-ai-advisor/tree/cp03-cloud-staging`
2. سجّل الدخول بـ **GitHub** واسمح لـ Render بالوصول إلى هذا المستودع فقط (Only select repositories).
3. ستظهر خانات المتغيرات. اكتبها **في Render فقط** (لا تُرسلها في أي محادثة):
   * `MH_ADMIN_USER`: اسم دخول المدير (مثل `owner`).
   * `MH_ADMIN_PASSWORD`: كلمة مرور قوية **10 أحرف على الأقل**.
   * `MH_STAFF_USER` / `MH_STAFF_PASSWORD`: حساب موظف تجريبي محدود (اختياري؛ 10 أحرف على الأقل).
   * `MH_ENRICH_CONTACT`: اختياري (بريد تواصل يُرسل لـOpen Beauty Facts ضمن تعريف التطبيق).
   * `MH_SECRET` يُولَّد تلقائيًا.
4. اضغط **Deploy Blueprint / Apply**. بعد اكتمال البناء يظهر رابط مثل `https://makeup-house-staging-xxxx.onrender.com`.
5. أرسل **الرابط فقط** (بدون كلمات المرور) ليتم التحقق الآلي منه.

## التحقق الآلي بعد النشر
```
node tests/staging-smoke.mjs https://<الرابط>
```
يتحقق من: HTTPS، الصحة، الشريط التجريبي، حجب البيانات بلا دخول (401)، عدم كشف تفاصيل الخادم، noindex، صفحة اختبار الجهاز، ورفض كلمة المرور الخاطئة.
فحوص ما بعد الدخول تعمل فقط إذا مُرّرت بيانات الدخول عبر متغيرات البيئة `SMOKE_USER/SMOKE_PASS` على جهاز المالك؛ وإلا يُثبتها المالك يدويًا من الهاتف (الخطوة 1 أدناه).

## خطوات التجربة من Samsung
1. افتح الرابط في **Chrome** أو **Samsung Internet** → يظهر شريط «نسخة تجريبية» → سجّل الدخول.
2. (اختياري) قائمة المتصفح ← «إضافة إلى الشاشة الرئيسية» لتثبيته كتطبيق.
3. **الكاميرا:** من شاشة الدخول افتح «اختبار الكاميرا وقارئ الباركود» ← «تشغيل الكاميرا» ← اسمح بالإذن ← وجّهها إلى باركود عبوة حقيقية. جرّب أيضًا رفض الإذن مرة للتأكد من ظهور رسالة واضحة.
   * إن ظهر «المتصفح لا يدعم BarcodeDetector» فجرّب Chrome، والإدخال اليدوي يبقى متاحًا دائمًا.
4. **المسح داخل التطبيق:** «مسح» ← كاميرا أو إدخال يدوي ← باركود منتج حقيقي ← يظهر نتيجة البحث العالمي (يحتاج مراجعة / غير معروف / تعذر الاتصال) مع المصدر.
5. **المراجعة (المدير):** «المزيد ← مراجعة المعلومات» ← قارن الاسم والعلامة والحجم والمكونات **بالعبوة نفسها** ← اعتمد أو عدّل أو ارفض.
6. **المستشار:** اكتب مثل «مرطب لبشرة جافة حساسة بدون عطر» ← راجع التفسير والتحذيرات والمستبعد وأسبابه.
6ب. **الصور (CP04):** افتح منتجًا ← «تصوير العبوة» ← التقط ← راجع المعاينة ← «حفظ الصورة». جرّب «إعادة الالتقاط»، و«من المعرض»، وتعيين صورة رئيسية، والحذف. للمدير: امسح باركود منتج عالمي ← «مراجعة المعلومات» ← قارن الصورة المقترحة بالعبوة ← اعتمد أو ارفض.
7. **قارئ HID** (إن توفر): في صفحة اختبار الجهاز، اضغط داخل الحقل وامسح 3 باركودات.
8. **سجّل كل نتيجة:** «المزيد ← ملاحظات التجربة» ← اختر الوظيفة والنتيجة ← «حفظ». عند الانتهاء: «مشاركة» (واتساب/بريد) أو «نسخ كنص». الملاحظات محفوظة على الهاتف نفسه، فلا تضيع عند سكون الخادم.
9. في صفحة اختبار الجهاز: «إنشاء التقرير» ← «نسخ» وأرسله مع الملاحظات.
