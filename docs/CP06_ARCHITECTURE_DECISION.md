# CP06 — قرار معمارية تطبيق Android المحلي (Local-first)

**الحالة:** مُنفَّذ على الفرع `cp06-android-local-first` · **البوابة:** `DEVICE VALIDATION PENDING` (لم يُختبر على هاتف Samsung فعلي) · **ليس CP06 FINAL.**

## 1) المطلوب
تطبيق Android حقيقي يخزّن المنتجات والصور والمكونات والتصنيف وحالات التحقق والحسابات **على الهاتف نفسه**، وتعمل وظائفه الأساسية **دون إنترنت ودون خادم Render**. الإنترنت فقط للمصادر الخارجية المعتمدة (Open Beauty Facts).

## 2) المقارنة الإلزامية
| المعيار | A: Kotlin أصلي (Room/SQLite) | **B: Capacitor هجين + SQLite WASM داخل التطبيق** | C: خادم Node محلي داخل Android (nodejs-mobile) |
|---|---|---|---|
| إعادة استخدام الكود الحالي | ~0%: إعادة كتابة الواجهة (≈20 شاشة) ومنطق المسارات والمستشار العلمي بلغة أخرى | **المسارات والمستشار العلمي والتصنيف والاستيراد والاستكشاف والصور تعمل بالكود نفسه دون نسخ** (نفس ملفات `server/src`) | عالية نظريًا |
| قابلية التنفيذ الآن | أسابيع؛ خطر انحراف المنطق العلمي عن النسخة المعتمدة | **نُفّذ وبُني APK واختُبر** | **غير ممكن:** nodejs-mobile على Node 18 ولا يملك `node:sqlite` (المشروع يتطلب Node 22) |
| قاعدة البيانات | SQLite أصلي | **SQLite حقيقي (3.54) كملف دائم في تخزين التطبيق الخاص (OPFS/SAH-pool)** | SQLite عبر إضافة أصلية تحتاج ترجمة لـ ARM |
| خطر تغيير فلسفة المستشار العلمي | مرتفع (إعادة كتابة) | **صفر: نفس الكود** | منخفض |
| الحجم | صغير | **≈5 م.ب** | +40 م.ب (محرك Node) |
| الأداء | الأفضل | كافٍ: 10,000 منتج، بحث ≈10–50 ملي ث (حاسوب؛ الهاتف أبطأ عدة مرات — يُقاس على الجهاز) | جيد |

**القرار: B.** هو الخيار الوحيد الذي يحقق «تطبيق حقيقي مستقل» الآن دون إعادة كتابة المنطق العلمي المعتمد (وهو ممنوع دون موافقة). A يبقى خيارًا مستقبليًا إن ظهرت حدود أداء على الجهاز. C رُفض لعدم توفر Node 22 / `node:sqlite` على Android.

**الدليل على الجدوى قبل البناء:** تجربة أولية أثبتت أن SQLite في OPFS يبقى بعد إعادة التحميل، و10,000 إدراج ≈45 ملي ث، وتخزين الصور BLOB يعمل.

## 3) كيف يعمل
```
WebView (Android System WebView)
 ├─ الواجهة الحالية web/ دون تغيير جوهري (RTL، نفس الشاشات)
 ├─ mobile/src/client.ts  ← يعترض fetch('/api/*') لنفس الأصل فقط ويرسله إلى العامل
 └─ Web Worker: mobile/src/worker.ts
      ├─ نفس مسارات server/src (routes, images, discovery, enrichment, science) عبر dispatch() محايد للنقل
      ├─ mobile/src/db.ts  ← واجهة متوافقة مع node:sqlite فوق SQLite WASM
      ├─ ترحيلات 001–005 مضمّنة، تُطبَّق إضافيًا فقط (غير مدمّرة)
      └─ ملف /makeup-house.db في التخزين الخاص بالتطبيق
```
* لا يوجد خادم ولا منفذ شبكي داخل الهاتف. كل طلب `/api` هو استدعاء دالة داخل العامل.
* الطلبات إلى مضيفات أخرى (Open Beauty Facts فقط في الكود) تمر كما هي، وعند انقطاع الإنترنت تُعرض «المصدر غير متاح» دون فقدان أي بيانات.

## 4) ما أُعيد استخدامه وما عُدّل وما لا ينتقل
| الفئة | التفاصيل |
|---|---|
| **أُعيد استخدامه كما هو** | المستشار العلمي `science/*`، المسارات `routes.ts`، الصور `images.ts`، الاستكشاف `discovery.ts`، موصل OBF، الاستيراد CSV/XLSX، التصنيف الموحد، الترحيلات، الواجهة `web/` |
| **عُدّل (دون تغيير السلوك على الخادم)** | `http.ts`: فُصل منطق التوجيه في `dispatch()` محايد للنقل (يستخدمه خادم Node والعامل معًا). الخادم ما زال يجتاز 121/121 |
| **بدائل للهاتف (shims)** | `node:crypto` (scrypt بنفس المعاملات N=16384,r=8,p=1 → نفس صيغة التجزئة، HMAC-SHA256)، `node:zlib` (inflate لملفات XLSX بحد حماية zip-bomb)، `Buffer` (مع base64url) |
| **خاص بالهاتف فقط** | إعداد أول تشغيل (إنشاء المدير)، النسخ الاحتياطي/الاستعادة المشفّرة، حفظ الملف عبر نافذة المشاركة |
| **لا ينتقل للهاتف** | خادم HTTP، Service Worker (التطبيق محلي أصلًا)، `MH_STAGING`، حسابات Staging، بيانات Staging (لا تُنقل تلقائيًا) |

## 5) الأمان وحدوده (بصراحة)
* **لا أسرار داخل APK:** فُحص الملف: لا عنوان Render ولا كلمات مرور ولا مفاتيح API. مفتاح توقيع الجلسات يُولَّد عشوائيًا **لكل تثبيت** عند أول تشغيل ويُحفظ في القاعدة المحلية (`local_meta`).
* **لا حسابات افتراضية:** أول تشغيل يطلب إنشاء حساب المدير (كلمة مرور ≥10). لا يمكن تكرار الإعداد بعد وجود مستخدم (409).
* **الصلاحيات نفسها:** الموظف لا يصل لإدارة الحسابات ولا للنسخ/الاستعادة (403)، مُختبر.
* **التخزين:** ملف القاعدة داخل مساحة التطبيق الخاصة؛ لا تقرؤه التطبيقات الأخرى دون Root. **غير مشفّر على القرص** (يعتمد على تشفير Android للجهاز). `allowBackup=false` حتى لا يُرفع إلى نسخ Google التلقائية دون قرار المالك.
* **حذف التطبيق أو «مسح بيانات التطبيق» يحذف القاعدة نهائيًا** → لذلك النسخ الاحتياطي المشفّر إلزامي (انظر CP06_ANDROID_GUIDE.md).
* **الجلسة:** رمز الدخول في `sessionStorage` → يُطلب تسجيل الدخول عند كل فتح جديد للتطبيق. قفل محاولات الدخول الخاطئة كما في الخادم.
* **نسخة واحدة في الوقت نفسه:** قاعدة OPFS تُفتح من نافذة واحدة فقط (هذا طبيعي في تطبيق Android ذي WebView واحد).
* **APK تجريبي (debug):** موقّع بمفتاح تطوير. **الانتقال لاحقًا إلى نسخة release بمفتاح آخر يتطلب إلغاء التثبيت = حذف البيانات** → خذ نسخة احتياطية قبل ذلك. لا نشر للعامة.

## 6) ما يحتاج تحققًا على الجهاز الحقيقي (لم يُدَّعَ)
الكاميرا داخل WebView (إذن CAMERA + getUserMedia)، توفر `BarcodeDetector` في WebView على Samsung (البديل: إدخال يدوي/قارئ HID)، حفظ النسخة عبر نافذة المشاركة، بقاء البيانات بعد إعادة تشغيل الهاتف وبعد تحديث التطبيق، وضع الطيران، الأداء الفعلي على المعالج. انظر `CP06_ACCEPTANCE.md`.
